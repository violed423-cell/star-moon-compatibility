# Star & Moon / 星と月

独自12キャラクターと独自16恋愛タイプを組み合わせた、2人の相性を考えるためのエンターテインメント・自己理解用 Web アプリです。科学的な心理検査、相手の気持ちや未来の予測ではありません。

## 起動・再現

Python 3.12.14 で検証しました。

```sh
python -m venv .venv
# Linux / macOS
. .venv/bin/activate
# Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python public_app.py
```

http://127.0.0.1:8003 を開きます。pyswisseph のバイナリがない環境では C/C++ コンパイラが必要です。GCC 環境では `CC=gcc CXX=g++ LDSHARED='gcc -shared' pip install -r requirements.txt` で構築できます。

```sh
python test_public_app.py
python test_calendar_engine.py
python compatibility_v1_6.py
python love_type_16_v1_4.py
python test_星月自動相性診断_v1_6.py
python test_release_review.py
python test_source_offer.py
python -m compileall -q .
```

## 診断ルール

日本標準時。年は立春、月は節入り、日は午前0時に切り替えます。出生時刻不明の場合は正午で暫定判定し、境界日には注意を表示します。出生地・真太陽時・流派差は未対応です。暦の回帰テストは専門的照合の代わりではありません。

日干の五行で候補を限定し、月柱スコア、年柱スコア、固定順位の順で選びます。配分は木2・火3・土2・金3・水2。16タイプの質問・名称と0～100の相性スコアも独自の参考値です。

## 暦計算の負荷対策

`solar_terms_jst.json` は元と同じ pyswisseph 2.10.3.2 の探索計算で事前生成した1899〜2027年の公開天文データです。利用者の情報ではありません。通常の1900〜2026年の生年月日は、コールド起動を含めリクエスト中の天文計算が不要です。対象外の年は元の計算を年単位・最大32年分キャッシュします。`generate_solar_terms.py` で再生成でき、毎年範囲を延長してテストしてください。`test_calendar_performance.py` は元計算との完全一致と境界・コールドPOST性能を検証します。独立した専門暦との照合を代替するものではありません。

Render/サーバーの技術・アクセスログが生成される可能性はあります。アプリが入力本文や診断結果をログ出力しないことと、ホスト側のログが存在しないことは異なります。

## 無料版と準備中の有料版

無料入口は `/`（`/free`、旧 `/birth`、旧 `/self` も同じ内容）です。2人の生年月日は必須。本人の12問は初期OFFの「自分の12問にも答える」で明示的に選んだときだけ検証します。各問も任意です。回答済みの項目だけを軸ごとに短く補足し、未回答は補完しません。16タイプ名は12問すべてが回答済みのときだけ表示します。OFF時は入力済み回答が送られても無視します。相手の回答・恋愛タイプは推測しません。

双方が12問ずつ答える総合診断は有料版用としてロジックを保持しますが、購入・決済・利用権の仕組みは未実装です。旧 `/both` と `POST /diagnose mode=both` はサーバー側で403として準備中案内へ制限し、任意のpaid/entitledパラメーターでも解除されません。`/premium` は案内のみです。

`test_modes.py` は任意回答の初期OFF・ON/OFF判定、必要項目、旧入口・直接POSTの制限を検証します。質問の開閉はCSS、判定とアクセス制御はサーバー側で、JavaScriptを必要としません。


## 無料診断・鑑定書導線のローカル改善

無料の％は既存の `ELEMENT_AFFINITY / 20 × 100` をそのまま使います。本人の任意回答は％を変えません。`fortune_content.read_birth_pair(date_a, date_b, time_a=None, time_b=None)` は二人の `Diagnosis`、`score`、組み合わせの説明、ヒントを返します。`read_self_answers({"q1": "A", ...})` は回答数と回答した軸の補足を返し、全12問のときだけ `complete_type` が入ります。相手の回答や気持ちは生成しません。

有料の双方向回答機能は引き続き閉じています。購入確認、決済、自動返信、自動納品、外部連絡フォームは追加していません。商品は未公開です。販売導線はココナラからの回答待ちのため保留し、鑑定書は簡潔な準備中説明だけを表示します。`COCONALA_PRODUCT_URL` の既存値は無視し、URLを設定しても購入ボタン・外部購入リンクは有効になりません。今は購入URLを設定しないでください。再開には、規約の確認と明示的な承認を受けた別途のコード変更が必要です。

### キャラクター画像

既存の12キャラクター画像を `assets/characters-source.jpeg` に置きます。元画像のSHA-256は `9ee979ce972b46e9da83221b7c905eeafb258720a642efd39639b80520eee115`、840342 bytes、1312×1199です。ライブラリ等からの正規の転送と目視検証を終えてから配置してください。ソース画像の人物部分をSVGのviewBoxで表示し、描き直しや色変更はしません。名前とエンジンIDを明示的に対応させています。元画像の色や五行ラベルは診断ロジックに使いません。特にリスの診断属性は既存どおり「火」です。

画像がない・ハッシュが違う・IDと名称が一致しない場合は代替画像を捏造せず「画像は準備中」と表示し、画像URLは404になります。承認された元画像をバイト変更せず同梱しています。配信時にもサイズとSHA-256を照合し、異なる画像を誤って表示しないようにしています。

### 検証

既存の全テストに加えて `python -m unittest test_fortune_content -v` を実行します。追加テストは12名称/ID/ROI、144通りの組み合わせと反転、既存％一致、未回答と部分回答、画像欠損、URLの設定有無にかかわらず購入リンクを出さない保留状態、繰り返し送信、入力エラーを確認します。
WindowsのPython 3.12ではpyswissephのビルドにMicrosoft C++ Build Toolsが必要になる場合があります。依存関係がない状態の構文検査・テストダブル使用の限定テストは、天文計算を含む通常の全テスト合格とは区別してください。


## 無料画面の曲線金額縁・月の意匠

`fortune_ornaments.py` は、曲線の巻き葉・中央の葉冠・横顔を持つ三日月と放射円を独自SVGで描きます。参考画像の画素・第三者の文字・透かしは含みません。アイボリー、淡青、淡桃、淡紫に、金の影色 `#9C702F`、本色 `#BE984D`、光色 `#F3DE9C` を合わせています。

装飾は `aria-hidden`、`focusable=false`、`pointer-events:none` とし、入力や読み上げを妨げません。画像の厳密ROI切り抜き、診断・質問・CTA・プライバシー処理とは分離しています。スマートフォン幅で装飾を縮小し、フォームを一列にします。追加検証は `python -m unittest test_ornate_design -v` です。
